# Cross-brief decisions (tech lead, 2026-09-02)

These resolve the open questions and sibling-contract deltas raised by the nine implementation briefs. Every brief must be amended to match. Numbered so briefs and code can cite them (D1, D2, ...).

- **D1 Identity.** `WebSocketConnectionOptions { url, workspace_id, session_id, token, takeover }`. `workspace_id` is the stable identity used for `ConnectionIdentifier`, workspace persistence (`name = workspace_id`, `host = None`, `user = None`) and the sandbox name. `session_id` is minted per connect by the control plane and is informational (telemetry, logs, the server's session bookkeeping). Persistence never depends on `session_id`.
- **D2 Reconnect budget.** Bounded: 20 attempts with exponential backoff capped at 8 s, then terminal state `ReconnectExhausted` with `last_close()` diagnostics. The shell exposes a host `reconnect()` that starts a new connection from scratch. A refresh that returns `RefreshError::Stopped` (control plane says the workspace is stopped) short-circuits retries immediately. `RefreshError::Unauthorized` is terminal.
- **D3 Session semantics on the server.** A *reconnect* (`Hello.reconnect = true`, epoch matches, server still holds state) attaches warm and replays per Zed's ack/replay protocol. A *fresh* session (`Hello.reconnect = false`, or stale epoch) resets the `HeadlessProject` (worktrees, language servers, git, settings observer restart); this is the accepted cost of a page reload. PTYs live in a server-level `PtyManager` outside `HeadlessProject` and survive fresh sessions: `detach_all` on session detach, `kill_all` only on process shutdown or explicit `CloseTerminal`. Close codes: 4001 superseded (takeover), 4005 session active (busy, no takeover), 1001 server going away. `Heartbeat` control frame every 5 s from the client; 16 MiB inbound frame ceiling on both sides. BUILD-SPEC section 4.2 is amended to say exactly this.
- **D4 Terminal restore is in scope for b3.** The client persists terminal ids, titles and working directories in workspace persistence. On a fresh session it calls `ListTerminals`, reattaches surviving terminals with `AttachTerminal { from_offset: 0 }` (scrollback replay) into their restored panes, and drops the rest. Nothing in b3 is deferred to a follow-up on this point.
- **D5 Control listener.** `serve` also binds a loopback control listener on `127.0.0.1:8446` authenticated with a secret read from `--control-secret-file`. Routes: `POST /control/lifecycle`, `POST /control/ports`, `POST /control/extensions` (install list from the manifest at startup and later). The public listener never exposes `/control`. `serve` takes `--allowed-origin <origin>` (repeatable) so `/files` CORS preflights from the shell origin succeed; the supervisor passes `manifest.allowedOrigins`.
- **D6 Unsaved buffers.** On `LifecycleNotice STOPPING` the client writes every dirty buffer's path, text and version into the client-state image (new table `unsaved_buffers`) and flushes `SaveClientState` inside the stopping window. On the next open those buffers are reopened dirty with the saved text. The client never writes to the workspace filesystem without the user saving.
- **D7 Client-state store.** One whole-database image (the `AppDatabase`, with `GlobalKeyValueStore` folded into it). `serialize()` and `restore_from()` run on `background_spawn`. Flush triggers: 15 s dirty timer, `visibilitychange` to hidden, `STOPPING`. The image is not importable into desktop Zed's shared database; BUILD-SPEC section 5.4 is amended (workspace layout follows the workspace across resumes, not to desktop).
- **D8 Private ports.** Four proxy slots, ports 8444 to 8447, declared at sandbox create. The control plane allocates one slot per private forward (four concurrent private forwards per workspace). The supervisor's proxy on each slot validates the `zs_port_session` HMAC cookie. The forward's `url` in the UI is the control plane `/open` link, which redirects to `https://<slot-host>/__zs/auth?zs_port_token=...&next=/` to set the cookie. BUILD-SPEC section 5.2 is amended.
- **D9 Rebuild tarball.** Includes `/workspaces` and `$HOME/.local/share/zed` (server data dir: client state, extensions, language-server downloads); extracted at `/`.
- **D10 Vendored dependencies.** Until a GitHub fork exists, `yawc`, `alacritty_terminal`, `lsp-types` and `agent-client-protocol` are vendored under `zed/vendor/<name>` as path `[patch]` entries, with `zed/vendor/README.md` recording the upstream revision and the intended git-patch form. No brief references a `<org>` placeholder.
- **D11 Wasm home directory** is `/home/web`; settings and keymap live under it at Zed's usual relative paths.
- **D12 Web keymap layer.** `assets/keymaps/web.json`, loaded last (after vim) on wasm only, remaps Cmd/Ctrl+W, T, N, Q, Shift+T and Ctrl+Tab. A `PlatformStyle` runtime override in the `ui` crate is permitted as a small upstream-shaped change.
- **D13 Activity ping** carries `lastInputAt`, `busy`, `phase` and `cpuBusyPct`. The control plane honours `busy`/`phase` (no idle stop while bootstrapping) and waits on the supervisor's health, never on fixed sleeps.
- **D14 Prebuild and devcontainer.** `zs-agent prebuild` (headless connect to warm language servers) is owned by b8. The devcontainer image builder workflow is a new brief b10, written after the first implementation round.
- **D15 AI provider proxy** (`/api/ai/*`) is a new brief b11, written after the first implementation round.
- **D16 Entry point for the shell.** b1 adds `workspace::open_remote_project_in_new_window_with_client(remote: Entity<RemoteClient>, app_state, paths, window_options, cx)` so the client-state image can be loaded over the session before `deserialize_remote_project` runs; b7 uses it.
- **D17 Terminal ownership.** b3 owns `crates/terminal/src/remote_pty.rs` and `TerminalType::Remote`; b6 keeps only its cfg gates in `terminal` and drops its remote-pty section. b3 calls `Terminal::expire_sync_update` at the end of `process_remote_output` and advances `Processor<SyncHandler>`.
- **D18 Supervisor contract.** No `ZS_CONTROL_SECRET` in the server environment (use `--control-secret-file`); control calls target `127.0.0.1:8446`; `POST /extensions` relay to the control plane; honour `manifest.repo.ref`; write settings `Value::String` verbatim; send `x-vercel-protection-bypass` from `ZS_BYPASS_SECRET`; stopping request budget exceeds the 5 s flush; report `cpuBusyPct`.
- **D19 Control plane contract.** No `source: { type: 'git' }` on image creates (the supervisor clones); rebuild tarball per D9; consume the installed-extensions relay; manifest fixture at `docs/contracts/fixtures/manifest.example.json`; honour D13.
- **D20 serve contract.** Exclude `AckTerminalOutput`, `ResizeTerminal`, `ListTerminals`, `AttachTerminal` from `is_input_envelope`; `PtyManager::detach_all` on detach (never `kill_all` on a fresh session); adopt b4's six contract items (flags, secret handling, control listener, asset route, `GpuiCommand` variants, `is_input_envelope` exclusions) and b1's section 7.12 contract (Hello-time arbitration with supersede, epoch, 4005, warm attach with replay-state reset, Heartbeat, 16 MiB).

# Decisions v2 (after the reconciliation pass, 2026-09-02)

These override any brief text and any CONTRACTS.md row that conflicts with them. Briefs are not re-edited before round 1; implementers apply these directly and reviewers check against them.

- **D21 Port map (settles D5, D8 and BUILD-SPEC 6.2).** Exposed ports, all declared at create and all public HTTPS: `8443` serve public listener (`/health`, `/rpc`, `/files`, `/extensions`); `8444`, `8445`, `8446`, `8447` private proxy slots (supervisor proxy, cookie-gated); `8448` supervisor health (unauthenticated minimal body `{ ok, phase, build, serverUp, uptimeSec }`, nothing sensitive); forward pool `3000, 3001, 4000, 5000, 5173, 8000, 8080, 8888`. That is 14 of the 15 allowed. Loopback only: `127.0.0.1:8450` supervisor API (`/ports`, `/git-token`, `/lifecycle`, `/extensions` relays, `/health` detail) and `127.0.0.1:8451` serve control listener (`--control-listen 127.0.0.1:8451`, `/control/*`). Env and flag defaults: `ZS_PROXY_SLOTS=8444,8445,8446,8447`, `ZS_HEALTH_PORT=8448`, `ZS_SUPERVISOR_URL=http://127.0.0.1:8450`, `DEFAULT_SUPERVISOR_URL` in the server = that value. The infrastructure set `8443-8451` is excluded from user forwards everywhere (ports routes, `verifyPortSession`, the supervisor port watcher reports them but the UI hides them).
- **D22 Heartbeat direction (amends D3).** The application-level `Heartbeat` control frame is server to client every 5 s (so a throttled hidden tab still learns the server is alive when it wakes). The server detects dead clients with WebSocket protocol-level ping every 5 s (browsers answer pong natively) and treats a socket with no frames of any kind for 90 s as dead. Zed's existing proto `Ping` from `ChannelClient` is unchanged.
- **D23 Close codes (amends D3).** `4001` superseded (takeover, or a stale epoch); `4002` client build mismatch; `4003` unauthorized after upgrade; `4005` session active and no takeover requested; `4006` malformed Hello; `1001` going away (SIGTERM, stop, or `RefreshError::Stopped` synthesized client-side); `1008` policy violation; `1009` frame too large. `4004` is retired. The shell maps `1001` to the `stopped` phase; `close_code_detail` names are `superseded`, `build_mismatch`, `unauthorized`, `session_active`, `bad_hello`, `going_away`.
- **D24 Warm and fresh (clarifies D3 and D20).** "Warm" means the server process is alive. A reconnect (same `instance`, epoch matches, server holds state) attaches warm and replays. A fresh session (different `instance`, or stale epoch) resets the `HeadlessProject`. The `PtyManager` is constructed at server level, outside `HeadlessProject`, exposed through a handle accessor; `detach_all` on session detach; no `kill_all` in `begin_fresh_session`.
- **D25 Hello.instance.** `Hello` gains `instance: String`, a per-boot nonce minted by the client. Session arbitration keys on `(workspace_id, instance)`. b1 does not compose nonces into the identifier string; `ConnectionIdentifier` stays `setup()`-style for the WebSocket transport.
- **D26 Connect response (clarifies D1).** `POST /api/workspaces/{id}/connect` returns `{ wsUrl, token, sessionId, workspaceId, serverBuild, sessionExpiresAt }`. `sessionId` is per connect and rotates on every refresh. The shell passes `workspaceId` and `sessionId` into `WebSocketConnectionOptions::new(url, workspace_id, session_id, token)`. Workspace persistence and the connection-pool key use `workspace_id` only.
- **D27 Trait additions.** b1 adds `fn supports_remote_pty(&self) -> bool { false }` to `RemoteConnection`, returning `true` for the WebSocket transport, and takes the `supports_extension_upload` gate offered by b4. b2 adds `ServeHooks::session_detached` next to `session_attached` and the four `is_input_envelope` exclusions.
- **D28 Terminals after stop and resume.** PTY processes do not survive a sandbox stop. On the next open the client recreates one shell per persisted terminal tab in its persisted working directory via `SpawnTerminal` (not blank panes). The supervisor exports `SHELL`, `HOME`, `USER`, `PATH`, `LANG` into the server's environment, never secrets.
- **D29 Names and shapes.** `ZS_CONTROL_URL` (origin plus `/api`) is canonical; `ZS_CONTROL_PLANE_URL` is removed. Lifecycle kinds are snake_case strings everywhere (`idle_stop_in`, `session_cap_in`, `stopping`, `resumed`), including the shell's `onLifecycle` type. The activity response is `ActivityDirective { idleStopAt, sessionCapAt, stop, forwards, serverTime }` (timestamp form). Bounded polling with 2 to 5 s pauses between probes satisfies D13; unconditional fixed waits do not.
- **D30 Host reconnect().** v1: the shell re-POSTs `/connect` and reloads the page. In-place re-dial is a later item.
- **D31 Vendoring conventions (clarifies D10).** Vendored crates live under `zed/vendor/<name>`, are listed in `[workspace] exclude`, not `members`, and are wired with path `[patch]` entries. `zed/vendor/README.md` is created by whichever lane lands first with this exact shape: a one-paragraph header, then one `## <crate>` section per crate containing `Upstream:` URL, `Revision:` hash, `Patch entry:` the Cargo line, and `Local changes:` a bullet list. Later lanes append sections; nobody rewrites the file.
- **D32 WasmFs flush.** b7 wires `WasmFs::take_dirty` into the hidden-tab and stopping flushes, uses `insert_dir` when seeding, and calls `flush_client_state` best-effort on `pagehide` in addition to the authoritative `visibilitychange` trigger.
- **D33 check-wasm.** `script/check-wasm` with no arguments checks the default package list; CI invokes it with no arguments; b7's wording follows b5.
- **D34 Client-state open-mismatch M17.** The b4/b7 position stands: one `AppDatabase` image with the global key-value store folded in, disjointness of keys enforced at review time.

# Decisions v3 (b10 devcontainer builder, 2026-09-03)

Recorded by the b10 lane per its brief §3.18; each extends or contradicts a written decision above or in BUILD-SPEC/CONTRACTS, and wins over them.

- **D35 Builder sandboxes.** A devcontainer image builder (`ib-<env>-<img id body>`) declares **no** ports and is created `persistent: false` with no snapshot retention (`snapshotExpirationMs`/`keepLastSnapshots` omitted); it is deleted explicitly by the workflow. D21 governs workspace ports and says nothing about builders.
- **D36 Inverted layering.** The user's `image`/`build.dockerfile` plus allowlisted Features (built by the devcontainer CLI) is the base of a repo image and our supervisor+server layer (`sandbox/image/builder/layer/`, `zs-layer-fixup.sh`) goes on top, amending BUILD-SPEC §6.3's "layered on our base". The layer guarantees `HOME=/vercel`, uid 1000, sudoers, `/workspaces`, git config and the CONTRACTS §11 `ENV`; Debian/Ubuntu and Fedora/RHEL families only (Alpine exits 90).
- **D37 Lifecycle extension.** `onCreateCommand` and `updateContentCommand` are supported beyond BUILD-SPEC §6.3's list and folded into the supervisor's post-create phase (`onCreate → updateContent → postCreate`, one 30-minute budget, one marker). `initializeCommand` stays unsupported (it would run in the builder).
- **D38 Manifest authority.** `manifest.devcontainer` is the `DevcontainerSpec` block (`docs/contracts/manifest-devcontainer.v1.json`) and is **authoritative** over the checkout when `source: "manifest"`; a control plane that sends only `{ configHash }` parses as `source: "checkout"` and the supervisor reads the file as before. Contradicts CONTRACTS §7.3's "informational". The post-create marker of a manifest-sourced config is `1:<contentHash>` (`MARKER_V`), never the bare hash.
- **D39 `customizations.zed` scope.** `customizations.zed.{settings,services,prebuild}` extend BUILD-SPEC §6.3's "settings and extensions". `settings` is restricted to a presentation-only allowlist (theme, fonts, tab/indent/wrap/format keys, `file_types`, `languages.<lang>.{tab_size,hard_tabs,soft_wrap,preferred_line_length,format_on_save,formatter∈auto|prettier|language_server}`); everything that names a program or a path (`lsp`, `terminal`, `tasks`, `context_servers`, `agent`, …) is dropped with a warning. Repo-declared `extensions` are offered in the dashboard and installed only after a per-repo maintainer opt-in (`repos.allowed_extensions`); a checkout's extensions are never auto-installed.
- **D40 Feature allowlist and services.** A Feature outside the allowlist (or outside `ghcr.io/devcontainers/features`) is **dropped with a `feature_not_allowed` warning** rather than failing the build (Codespaces fails). The supervisor gains `Phase::Services` and starts `dockerd` (`sudo -n dockerd`, its own process group, `docker info` readiness ≤ 30 s, non-fatal) when the manifest's `services` (from `customizations.zed.services` or the `docker-in-docker` Feature) asks for it, resolving b8 §7 item 24; its log source is `services`.

# Decisions v4 (browser boot fixes, 2026-09-04)

- **D41 Worktrees are trusted in the browser.** The web settings overrides (`zed_web_core::WEB_SETTINGS_OVERRIDES`) set `session.trust_all_worktrees = true`: the sandbox is the user's own VM, so Zed's "Restricted Mode" prompt for the checkout added nothing but a click. Native Zed keeps its default.
- **D42 The main thread never parks.** `parking_lot_core` is vendored (`vendor/parking_lot_core`) so that a thread marked by the embedder spins instead of executing `memory.atomic.wait32`, which browsers forbid on the main thread; `gpui_web` marks the main thread at dispatcher creation. Rationale in `vendor/README.md`: the thrown JS exception skipped Rust destructors and leaked gpui's `App` borrow, the "RefCell already borrowed" floods seen after boot. A genuine deadlock now hangs the tab instead of crashing it, which is the native behaviour too.

# Decisions v5 (b11 AI proxy, 2026-09-04)

Recorded by the b11 lane per its brief §7 item 16.

- **D43 `language_models` runs on wasm behind the AI proxy (supersedes b9 §7 item 16).** The browser build initialises `language_models`; the `localhost` providers (Ollama, LM Studio, llama.cpp — unreachable under the editor CSP), Bedrock and the ChatGPT subscription are gated out under `cfg(target_family = "wasm")`. b11 seeds every proxied provider's `api_url` to `<origin>/api/ai/<id>` (nine `language_models` providers and `edit_predictions.codestral`) in the web default settings and installs `zed_web::ai::ProxyCredentialsProvider` as the `zed_credentials_provider` global: it answers the placeholder `zs-proxy-v1` for providers the control plane holds a key for and the proxy injects the real key. Keys live in `ai_keys` (per user, AES-256-GCM envelopes), not in `secrets`; `api/ai/` is outside the Clerk matcher; `lib/ratelimit.ts` carries `user.ai.requests` (120/min) and `user.ai.keys` (30/min). Edit predictions in the browser go through `zed_web::web_edit_prediction` (Codestral via the proxy, an OpenAI-compatible FIM endpoint only at a proxied `compat/<name>` URL; Copilot, Zed, Mercury and Ollama yield no provider with a one-time notice). `ZsBootConfig.origin` exists for harnesses only; the shell relies on `window.location.origin`. One deviation from b11 §3.17 is accepted: a 2xx `PUT /api/ai/keys/<id>` whose confirming `GET` fails outright (429/5xx) counts as saved; only an inventory that was read and still lacks the provider is an error. BUILD-SPEC §8 line 402 ("Browser CORS blocks most providers") and §7.9 line 387 (keys decrypted only in workflows) are amended as b11 §7 item 1 describes.

# Decisions v5 (prototype simplification, 2026-09-04)

Ray's direction on 2026-09-04; each wins over BUILD-SPEC, CONTRACTS and every earlier decision it touches.

- **D43 Turso instead of Postgres.** The control plane's database is libSQL: Turso in deployment (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, the Vercel Marketplace Turso integration), a local `file:` database in development and `:memory:` in tests. Drizzle stays; the schema moves to `drizzle-orm/sqlite-core` (enums as text enums, `jsonb` as JSON text, timestamps as integer milliseconds), migrations are regenerated from scratch, and `pg`, PGlite and Docker Postgres leave the repository. No Marketplace Postgres.
- **D44 No Redis.** The `KV` interface of `lib/redis.ts` (locks, counters, sorted sets, TTLs) is implemented on the same libSQL database (`kv` and `kv_zset` tables with expiry columns, sweep on read and from the cron); rate limiting is a small window limiter over that KV. `@upstash/*` leaves the repository; `ZS_KV=memory` keeps the in-process store for tests.
- **D45 Open access, no Clerk, no GitHub App.** The prototype is one shared space: every request is the same public viewer, there are no accounts, organisations are a single implicit one, and the homepage (`/`) lists and manages every workspace. `GET /new/:owner/:repo` creates a workspace for `https://github.com/:owner/:repo` (default branch) and redirects to `/w/:id`. Public repositories clone without credentials; an optional `GITHUB_TOKEN` environment variable is used for private ones and for API rate limits. Clerk, the sign-in page, the Clerk webhook and the GitHub App installation flow are removed; the sandbox-facing JWTs (BUILD-SPEC 8) are unchanged.
- **D46 Operator layout defaults and AI off.** `zed_web_core::WEB_LAYOUT_DEFAULTS` carries the operator's own Zed layout (dock placement for the project, git, outline, collaboration and terminal panels, tab bar and title bar, font sizes, line height, vim mode, autosave on focus change, unified diffs, inline diagnostics and blame) and sets `disable_ai: true` for the whole browser editor. It is merged after `WEB_SETTINGS_OVERRIDES` and before the AI-proxy URLs, and a user's own `settings.json` still wins. Font families, themes and icon themes are deliberately excluded: the bundle packs Lilex, IBM Plex Sans and the `one`/`ayu`/`gruvbox` themes only, so naming absent assets would silently fall back. The block is taste, not a platform requirement, which is why it is a separate constant from the browser overrides.
- **D47 First-run layout and a title bar that fits a tab.** A workspace that restored no client-state image gets the file tree and a terminal opened for it (`zed_web::workspace_chrome::set_first_run`, driven by `load_client_state` returning no image); a returning tab keeps whatever layout it left, closed docks included. The title bar hides the project host and name (`show_project_items: false`), the onboarding banner, the avatar, the sign-in button and the user menu: one tab is one project on a machine the person never chose, so only the branch and worktree names carry information.
